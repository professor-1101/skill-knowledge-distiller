# Data model

JSONL throughout: append-only, mergeable, greppable, no whole-file rewrites,
and corruption costs one line rather than one file. The two derived artifacts
(`concepts.jsonl`, `gaps.jsonl`) are regenerated by definition, and the indexer
preserves rows other stages wrote.

## Claim

The unit of evidence. Full JSON Schema in `templates/claim.schema.json`.

```json
{
  "id": "source-slug/ch07/s02/c04",
  "unit": "source-slug/ch07/s02",
  "chunk": "source-slug/k0031",
  "type": "principle | rule | pattern | anti-pattern | tradeoff | example | definition",
  "statement": "Split a boundary when two owners need different models of one entity.",
  "condition": "two or more owners hold conflicting invariants on one entity",
  "consequence": "integration cost rises; model clarity is preserved",
  "defines": ["bounded-context"],
  "mentions": ["ubiquitous-language"],
  "evidence": {
    "source": "source-slug",
    "locator": "p.191",
    "support": "direct | inferred",
    "excerpt_hash": "sha256:…"
  },
  "origin": "source | model",
  "confidence": 0.9,
  "corroboration": 1,
  "prompt_version": "extract@a1b2c3d",
  "extracted_at": "2026-08-09T11:04:00+00:00"
}
```

`condition` and `consequence` are what make this a claim rather than a summary
sentence, and they are enforced at write time rather than reviewed later.
`defines`/`mentions` make gap detection a set operation. `excerpt_hash` proves
the evidence was read without storing source text at length.

## Rule

```json
{
  "id": "rule/split-on-the-ownership-seam",
  "cluster": "boundaries",
  "name": "Split on the ownership seam",
  "when": "two or more owners hold conflicting invariants on the same entity",
  "then": "split along the ownership seam",
  "because": "model clarity compounds; integration cost is paid once at the boundary",
  "unless": [
    { "clause": "the owners are merging within the planning horizon",
      "from": "source-slug/ch09/s01/c07" }
  ],
  "cost": { "status": "unknown", "gap": "the source states no price for this rule" },
  "anti_patterns": ["ap/shared-store-integration"],
  "derived_from": ["source-slug/ch07/s02/c04"],
  "corroboration": 1,
  "confidence": 0.9
}
```

`name` is a short imperative, never a truncation of the statement. Each
boundary clause carries the claim that established it, because R4 draws
exceptions from other units and other sources and that link exists nowhere
else. `cost` shows the declared-unknown union in use.

## Derivation manifest

No field is maintained by hand where it can be computed. For EPUB that is
nearly all of them, which is the point of the format change.

| Field | Derived from |
|---|---|
| segment `kind` | the XHTML: has prose, has media, both, or neither |
| `nav_title`, `headings`, `anchors`, `media` | the markup |
| `corpus.jsonl` rows | nav or NCX, plus the spine |
| `corpus.jsonl` status | claims + probes + prompt hash (`sync-corpus.mjs`) |
| chunk `unit` | the TOC entry covering its start offset |
| chunk and unit ids | spine index and ordinal, never a running count |
| claim `unit` | its chunk, and cross-checked against it |
| `confidence` | the rubric (`confidence.mjs`) |
| digests and counts | the bytes, recorded **and** re-verified |

What remains human: the gap `reason`, and the judgements at R2–R7.

## Chunk and page

A *segment* is one spine document — ordered, addressable, digest-bearing. It is
what a page was, which is why the store keeps the page vocabulary.

```json
{ "page": 7, "locator_scheme": "epub-spine", "href": "OEBPS/ch03.xhtml",
  "spine_index": 6, "linear": true,
  "kind": "text | image | mixed | empty",
  "nav_title": "Three: Ends", "char_count": 3184, "text_sha256": "…",
  "headings": [{ "level": 1, "title": "Three: Ends", "offset": 0 }],
  "anchors":  [{ "id": "sec2", "offset": 1200 }],
  "media":    [{ "kind": "image", "src": "fig3.png", "alt": "…", "offset": 900 }],
  "extractor": "epub-builtin@1.0.0" }

{ "id": "source-slug/s006/k000", "doc": "source-slug",
  "page": 7, "href": "OEBPS/ch03.xhtml",
  "locator": "OEBPS/ch03.xhtml@0-6000",
  "char_start": 128400, "char_end": 134400, "chars": 6000,
  "sha256": "…", "unit": "source-slug/s006/u00" }
```

Chunk offsets are absolute in one continuous character space across the book,
so a locator resolves without reconstructing per-document layout. The id is
structural: spine index, then ordinal within that document. A positional id
would renumber everything after an insertion and orphan every claim that
referenced one.

## Disposition

```json
{ "claim": "source-slug/ch07/s02/c04",
  "disposition": "promoted | merged | supporting | context | not-transferable | platitude | deferred",
  "target": "rule/split-on-the-ownership-seam",
  "reason": "same rule as ch09/s01/c11, different vocabulary",
  "stage": "R2", "decided_at": "2026-08-09T09:12:00+00:00" }
```

Invariant: **claims − dispositions = ∅ before a certificate may be issued.**
`not-transferable` and `platitude` require a non-empty reason, because those
two are where a lazy refinement pass would quietly discard the corpus.

## Checkpoint

```json
{ "unit": "…", "chunk": "…", "stage": "R0",
  "prompt": "templates/prompts/extract.md", "prompt_hash": "…",
  "output": "claims/…", "output_hash": "…",
  "model_id": "…", "at": "…" }
```

Append-only; later rows win. `prompt_hash` invalidates; `model_id` never does.

## Confidence

Computed by rubric, never judged. Hand-assigned confidence is unreproducible
and cannot be recomputed when new corroboration arrives.

```
base                0.90 support=direct · 0.65 support=inferred
                    0.50 origin=model  (overrides, regardless of support)
corroboration       +0.00 one source · +0.05 two · +0.10 three or more
cross-source        +0.05 corroborated by a DIFFERENT source, not a second
                    session over the same one
confidence = clamp(base + bonuses, 0, 1)
```

`origin: model` caps at 0.50 regardless: repetition of a model inference is not
corroboration of a fact.

## Configuration

`.distill.json` at the store root, optional. Absent means defaults apply.

```json
{
  "id_pattern":   "^[a-z0-9-]+/s\\d{3}/u\\d{2}/c\\d{2}$",
  "unit_pattern": "^[a-z0-9-]+/s\\d{3}/u\\d{2}$",
  "extractors":   { "primary": "epub-builtin" },
  "enumerate":    { "depth": 2 },
  "chunk":        { "target_chars": 6000, "overlap": 0 },
  "saturation":   { "ratio": 0.05 }
}
```

Only the identifier shapes are configurable, because "chapter" and "section"
are book vocabulary and the methodology is meant to outlive that. Nothing else
in the pipeline reads the shape. An invalid file stops the work rather than
being worked around.
